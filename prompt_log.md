# Prompt Log

**AI tool used:** Claude (Cowork agentic session, Claude Sonnet), working directly in a cloud sandbox with shell access to write, run, and test the code, plus a linked-device bridge to read/write files on my own computer.

I gave the assignment PDF to Claude and asked what to do with it. Given I had limited time before the deadline, the key prompts/decisions that shaped this implementation were:

1. **Initial framing** — I uploaded the HW4 assignment PDF and asked "what should I do with this assignment." Claude read the spec, flagged that it was due in ~3.5 hours, and summarized the required deliverables (backend on Render, frontend on GitHub Pages, two repos, README, prompt log, video, Google Form).

2. **Scoping decision** — Claude looked at my existing portfolio repo (a mostly-placeholder `projects.html`, an existing `contact.html`, and a game called Void Hop already linked from the homepage) and proposed two options: (a) a low-risk guestbook/contact backend with no external API keys or database, or (b) an "Ask Oulan" AI chatbot widget using an LLM API. Given the assignment's own "caution on scope" section (which warns that juggling multiple services, not the code itself, is what usually causes trouble under time pressure) and the time remaining, I chose option (a): **guestbook backend, extending the existing Contact page.**

3. **"Handle secrets the way the assignment wants"** — I asked for the implementation to include a real demonstration of environment-variable secret handling (not just claim it in the README), which led to adding the `ADMIN_TOKEN`-gated `DELETE /messages/<id>` endpoint: a small moderation feature that's genuinely broken if the token isn't set, and unauthorized without the correct header.

4. **"Keep dependencies minimal"** — When testing locally, `flask-cors` wasn't resolvable in the sandbox's package mirror. Rather than fight the sandbox, Claude replaced it with a hand-rolled CORS `after_request` hook plus an explicit `OPTIONS` preflight handler, and dropped the dependency from `requirements.txt`. This was also just a better outcome for deployment: fewer packages that can fail to install on Render.

5. **"Test everything before calling it done"** — Claude ran the Flask app locally and hit every route with curl (health check, empty GET, valid POST, POST with missing fields, POST with a non-JSON body, DELETE with no/wrong/correct token, and an OPTIONS preflight) before writing this up, to confirm status codes and JSON shapes actually matched what the README claims.

All code (Flask app, error handling, README, this log) was generated by Claude and reviewed/tested end-to-end by me before submission. I read through `app.py` and asked Claude to explain the CORS preflight handling and the admin-token logic so I could speak to both in the demo video.
